# 원더핀 제품 MVP 통합 런칭 계획

## 1. 계획의 전제

원더핀의 가족용 웹앱과 운영자용 SaaS인 원더핀 파트너는 별개의 제품처럼 보이지만 하나의 거래를 양쪽에서 처리한다. 따라서 둘 중 하나를 완성한 뒤 다른 하나를 만드는 방식이 아니라, **프로그램 한 건이 등록되고 가족 한 팀이 예약한 뒤 운영자가 안내하는 전체 흐름**을 두 화면에서 함께 완성한다.

인스타그램과 첫 원더팩은 제품 개발과 병행하지만, 원더핀 웹앱보다 먼저 출시한다.

- 인스타그램: 초기 가족 유입과 니즈 검증
- 첫 원더팩: 원더핀의 탐구 경험을 제품보다 먼저 체험하게 하는 콘텐츠
- 원더핀: 가족이 장소·프로그램·원더팩을 발견하고 이용하는 PC·태블릿·모바일 반응형 웹앱
- 원더핀 파트너: 운영자가 프로그램과 예약을 처리하는 SaaS

## 2. 첫 제품이 증명할 한 문장

> 운영자가 원더핀 파트너에 프로그램을 등록하면 가족이 원더핀에서 발견하고 예약할 수 있으며, 운영자는 참가자를 안내하고 가족은 현장에서 원더팩을 사용할 수 있다.

이 문장을 실제 사용자와 거래로 증명하는 데 필요하지 않은 기능은 첫 MVP에서 제외한다.

## 3. 공동 핵심 흐름

1. 운영자가 파트너 계정을 만들거나 초기 운영팀의 승인을 받는다.
2. 운영자가 프로그램, 장소, 연령, 일정, 정원, 가격과 준비물을 등록한다.
3. 프로그램이 가족용 원더핀에 공개된다.
4. 가족이 프로그램 상세를 확인하고 참가자 정보를 입력해 예약·결제한다.
5. 운영자가 예약과 참가자 명단을 확인한다.
6. 가족에게 집합장소, 준비물과 일정 안내가 전달된다.
7. 가족이 프로그램에 참여하고 연결된 원더팩을 사용한다.
8. 참여 후 가족이 후기를 남기고 운영자가 재참여 데이터를 확인한다.

### 공유 데이터

두 제품은 처음부터 아래 데이터를 함께 사용해야 한다.

- 사용자와 가족 프로필
- 운영자와 파트너 상태
- 장소
- 프로그램
- 프로그램 회차
- 가격, 정원과 예약 가능 상태
- 예약, 참가자와 결제 상태
- 안내 발송 기록
- 후기
- 원더팩과 프로그램·장소 연결

같은 데이터를 가족용과 운영자용으로 따로 저장하지 않는다.

## 4. 가족용 원더핀 MVP

### 반응형 웹 원칙

원더핀은 모바일 전용 화면이 아니라 PC, 태블릿과 모바일에서 모두 사용할 수 있는 반응형 웹으로 개발한다.

- 모바일: 이동 중 장소 탐색, 예약, 현장 원더팩 이용에 최적화
- 태블릿: 부모와 아이가 함께 원더팩을 보고 활동하기 좋은 2열·넓은 화면 구성
- PC: 장소와 프로그램 비교, 상세 정보 확인과 예약 관리에 적합한 레이아웃
- 터치와 마우스·키보드 입력을 모두 지원
- 화면 크기가 달라도 동일한 정보와 기능에 접근 가능
- 글자 확대, 키보드 탐색, 명확한 대비와 대체 텍스트 등 접근성 고려

### 반드시 포함

- 모바일 웹 기반 홈
- 방문하기 좋은 장소 목록과 상세 소개
- `이번 주 아이와 갈 원더핀`
- 프로그램 목록과 상세
- 연령·날짜·지역의 최소 필터
- 예약자·참가 어린이 정보 입력
- 예약·결제와 완료 화면
- 내 예약과 참가 안내 확인
- 장소별 원더팩 소개와 이용
- 참여 후 후기 작성

### 초기 홈 구성

사업 문서에 정의된 모든 홈 섹션을 한 번에 구현하지 않는다. 첫 MVP는 다음 세 가지를 우선한다.

1. 이번 주 아이와 갈 원더핀
2. 우리 아이에게 맞는 프로그램
3. 방문하기 좋은 원더 장소
4. 첫 원더팩

`이번 주말 무료 탐구활동`, `장소별 원더팩 전체 탐색`, `해외여행 원더핀`은 콘텐츠와 데이터가 충분해진 뒤 확장한다.

### 원더 장소 목록

초기 운영자나 예약 가능한 프로그램이 적어도 가족용 앱이 비어 보이지 않도록, 향후 원더프로그램이 만들어질 가능성이 높은 장소를 먼저 목록화한다.

각 장소에는 다음 정보를 제공한다.

- 장소명, 유형, 지역과 공식 웹사이트
- 권장 연령과 예상 체류시간
- 실내·야외 여부와 날씨 영향
- 관람료, 예약 필요 여부와 운영시간
- 대중교통, 주차와 유아 편의시설
- 아이와 볼 관찰 포인트
- 연결된 원더팩
- 공식·무료 프로그램 외부 링크
- 원더핀 운영자가 개설한 원더프로그램
- `이 장소의 프로그램 요청하기`
- 정보 확인일과 출처

공식 프로그램 외부 링크와 원더핀에서 예약 가능한 프로그램을 명확히 구분한다. 프로그램이 없는 장소에는 가짜 상품이나 모집 예정 문구를 노출하지 않고, 원더팩·관찰 포인트·프로그램 요청 기능으로 수요를 수집한다.

## 5. 원더핀 파트너 MVP

### 반드시 포함

- 운영자 가입·로그인과 기본 프로필
- 프로그램 등록·수정·미리보기
- 회차, 정원, 가격과 예약 마감 설정
- 직접 모객용 공유 링크
- 인앱 예약과 직접 모객 예약 구분
- 예약 상태와 참가자 명단
- 집합장소·준비물·일정 안내
- 취소·환불 상태 처리
- 후기 목록과 최소 성과 지표

### 최소 대시보드

- 예정 프로그램
- 회차별 예약 수와 잔여석
- 확인이 필요한 예약·취소
- 발송할 안내
- 최근 후기

후기와 재참여 분석은 첫 MVP에서 복잡한 CRM이 아니라 후기 수, 작성률, 재예약 여부를 확인하는 수준으로 제한한다.

## 6. 내부 운영 도구

초기에는 고객 화면만큼 내부 운영 화면도 필요하다.

- 운영자 승인과 상태 변경
- 프로그램 검수·공개·비공개
- 예약·결제·환불 상태 확인
- 원더팩 등록과 장소·프로그램 연결
- 문의 및 사고 기록

사용자가 적은 단계에서는 완전한 자동화보다 안전하게 수동 처리할 수 있는 관리자 기능을 우선한다.

## 7. 첫 MVP에서 제외

- 네이티브 iOS·Android 앱
- 소셜 로그인 전체 구성
- AI 프로그램·콘텐츠 자동 생성
- 강사별 권한과 정산
- 고급 CRM·쿠폰·자동 세그먼트
- 광고·노출 부스팅
- 복잡한 추천 알고리즘
- 전국 장소 DB
- 해외 장소, 다국어와 해외 결제
- 원더팩 제작 도구

## 8. 초기 운영자 부족 대응

운영자가 충분히 모일 때까지 기다리지 않는다. 가족에게는 장소 정보와 원더팩으로 가치를 제공하고, 축적된 장소별 관심을 운영자 모집 근거로 사용한다.

### 공급이 없어도 작동하는 가족 가치

- 검수된 원더 장소 목록과 상세 정보
- `이번 주 원더핀` 큐레이션
- 장소별 원더팩
- 기관이 직접 운영하는 공식·무료 프로그램 링크
- 장소별 원더프로그램 요청과 대기 등록

### 운영자 확보 방식

1. **콘시어지 온보딩** - 초기 10명은 원더핀 팀이 프로그램 상세와 일정을 대신 등록한다.
2. **직접 모객 우선** - 운영자가 기존 SNS 고객을 공유 링크로 관리하게 해 초기 플랫폼 트래픽 부담을 낮춘다.
3. **장소별 수요 증명** - 장소 저장, 원더팩 이용, 프로그램 요청 수를 보여주며 해당 장소 운영자를 모집한다.
4. **기존 운영자 역추적** - 기관 프로그램, SNS, 블로그와 공개 상품에서 실제 활동 중인 도슨트·생태교육가를 찾는다.
5. **첫 파트너 혜택** - 제한된 베타 기간 SaaS 무료, 등록 대행과 성과 리포트를 제공한다.
6. **프로젝트형 공급** - 필요하면 검증된 교육자에게 파일럿 원더프로그램을 기획·운영하도록 의뢰한다.
7. **기관·커뮤니티 제휴** - 박물관 교육팀, 숲교육 단체와 지역 부모 커뮤니티에 공동 테스트를 제안한다.

### 콜드스타트 원칙

- 장소 50곳과 운영자 1명을 넓게 보여주기보다 장소 클러스터 3~5곳에서 프로그램 밀도를 만든다.
- 운영자가 없는 프로그램을 원더핀 상품처럼 보이게 하지 않는다.
- 기관 시설 안에서 민간 유료 프로그램을 운영할 때는 장소별 허가·영리행위·단체관람·해설 규정을 사전에 확인한다.
- 운영자 수보다 실제 개설 프로그램, 예약 처리와 재등록을 공급 지표로 본다.

## 9. 병행 실행 로드맵

### Phase 0. 정의와 준비 - 1~2주

#### 제품

- 가족·운영자 공동 핵심 흐름 확정
- 화면 흐름과 클릭 가능한 저해상도 프로토타입
- 공유 데이터 모델과 권한 설계
- 결제, 알림, 개인정보와 환불 정책 조사
- 개발 환경과 배포 구조 결정

#### 인스타그램

- 프로필, 브랜드 소개와 주 2회 템플릿 준비
- 첫 4주 정기 콘텐츠 8편의 소재 확정

#### 원더팩

- 첫 원더팩 방향 선정
- 현장 조사와 대상 연령별 실행 반응 확인
- 콘텐츠 구조와 검수 기준 확정

### Phase 1. 인스타그램·원더팩 선출시와 제품 골격 - 3~4주

#### 제품

- 로그인·사용자·운영자 기본 구조
- 장소·프로그램·회차 데이터 생성
- 반응형 원더 장소 목록·상세 초안
- 원더핀 프로그램 목록·상세 초안
- 원더핀 파트너 프로그램 등록 초안

#### 채널·콘텐츠

- 인스타그램 브랜드 소개 공개
- 첫 원더팩 동시 출시
- 신청자가 웹형·PDF형 중 이용 형태 선택
- 5분 원더 미션·이번 주 원더핀 주 2회 발행 시작
- 원더팩 신청·실행·반복 반응 수집

이 단계에서 가족용 원더핀 웹앱은 공개하지 않는다. 별도 랜딩페이지 또는 폼을 통해 원더팩을 제공하고, 인스타그램 활성화·콘텐츠 검증·브랜드 정체성 전달에 집중한다.

### Phase 2. 예약의 양쪽 연결 - 5~8주

#### 가족용

- PC·태블릿·모바일 반응형 장소 목록과 상세
- 예약자·참가자 입력
- 결제 또는 제한된 베타 결제 흐름
- 예약 완료·내 예약·안내 확인

#### 운영자용

- 회차·정원·가격 관리
- 직접 모객 링크
- 예약·참가자 명단
- 안내 발송과 취소 상태 처리

#### 검증

- 운영자 2~3명 프로그램을 직접 온보딩
- 장소 20곳 이상을 검수해 목록화
- 테스트 예약 20건 이상
- 주요 오류와 수동 운영 절차 기록

### Phase 3. 비공개 통합 베타 - 9~12주

- 운영자 5명 이상
- 프로그램 10개 이상
- 실제 가족 20팀 이상
- 실제 유료 예약 30건 이상
- 첫 원더팩 실제 이용 10건 이상
- 예약·안내·취소 흐름을 4주 동안 운영
- 중대한 개인정보·결제·정원 오류 0건

12주차에 공개 범위 확대, 추가 검증 또는 MVP 수정 중 하나를 결정한다.

## 10. 통합 런칭 게이트

두 제품의 화면이 존재하는 것만으로 출시하지 않는다. 아래 조건을 모두 충족해야 통합 베타로 본다.

- 운영자가 직접 프로그램과 회차를 등록할 수 있다.
- 가족이 공개된 프로그램을 보고 실제 예약할 수 있다.
- 가족이 PC·태블릿·모바일에서 장소와 프로그램을 탐색할 수 있다.
- 예약과 정원이 양쪽 화면에서 동일하게 보인다.
- 운영자가 참가자 명단을 확인하고 안내할 수 있다.
- 취소·환불 시 양쪽 상태가 일치한다.
- 가족이 프로그램 또는 장소에 연결된 원더팩을 이용할 수 있다.
- 개인정보, 결제와 아동 안전 관련 운영 절차가 준비되어 있다.

## 11. 초기 성과 지표

### 제품

- 운영자 프로그램 등록 완료시간 15분 이내
- 프로그램 상세 → 예약 시작 전환율
- 예약 시작 → 결제 완료율
- 예약·정원 불일치 0건
- 안내 처리시간 절감률
- 운영자 프로그램 재등록률

### 콘텐츠·채널

- 5분 원더 미션 저장률과 실제 실행 후기
- 이번 주 원더핀 저장률·공유율·프로필 방문
- 첫 원더팩 이용률과 완료율
- 인스타그램 → 원더팩 → 웹앱 이동 수

### 공급·거래

- 활성 운영자 수
- 등록 프로그램과 회차 수
- 유료 예약 수와 GMV
- 취소·환불·노쇼율
- 후기 작성률과 재참여 의향
