# 원더핀 의사결정 기록

## D-001 AI 조직은 Codex 프로젝트 에이전트로 운영

- 날짜: 2026-07-14
- 상태: 확정
- 결정: 별도 LLM API 기반 오케스트레이터를 만들지 않고 Codex 프로젝트 커스텀 에이전트, 저장소 기반 업무 기록과 예약 작업을 사용한다.
- 이유: 초기 고정비와 API 사용량 변동을 줄이고, 사용자가 작업과 승인을 직접 확인할 수 있게 한다.
- 영향: 에이전트의 지속 상태는 대화가 아니라 저장소의 `operations/`와 `tasks/`에 기록한다.

## D-002 제품은 세 개의 웹앱으로 분리

- 날짜: 2026-07-14
- 상태: 확정
- 결정: 가족용 `apps/web`, 운영자용 `apps/partner`, 내부 관리자용 `apps/admin`으로 구성한다.
- 이유: 사용자와 권한, 배포 주기가 다르지만 핵심 데이터 모델과 UI 기반은 공유해야 한다.
- 영향: 앱은 공유 패키지와 동일 데이터베이스를 사용한다.

## D-003 외부 영향이 있는 행동은 사용자 승인 후 실행

- 날짜: 2026-07-14
- 상태: 확정
- 결정: 게시, 연락, 유료 행동, 배포, 운영 DB 및 실제 고객 상태 변경은 사용자 승인 후 실행한다.
- 이유: 브랜드, 비용, 개인정보와 운영 사고 위험을 통제하기 위해서다.

## D-004 첫 검증 Gate는 인스타그램 가족 수요와 원더팩 실행 행동에 집중

- 날짜: 2026-07-14
- 상태: 확정
- 결정: 2026년 8월 14일까지의 Gate 1에서 운영자·가족 인터뷰 목표를 제외하고, 인스타그램 발행·가족 리드·원더팩 신청·실행·반복 반응을 핵심 KPI로 사용한다.
- 이유: 초기에는 말로 표현한 의향보다 실제 채널 반응과 원더팩 실행 행동으로 가족 수요를 검증한다.
- 영향: 운영자 SaaS라는 최종 출시 목표는 유지한다. 운영자 검증은 Gate 2의 수동 온보딩과 실제 예약 처리에서 거래 행동으로 검증한다.

## D-005 `이번 주 원더핀`은 장소와 프로그램 큐레이션으로 운영

- 날짜: 2026-07-16
- 상태: 확정
- 결정: 인스타그램 정기 시리즈 `이번 주 원더핀`은 장소에서 볼 탐구 포인트를 짚어주는 콘텐츠가 아니라, 이번 주말 갈 만한 장소와 그 장소에서 참여할 수 있는 프로그램을 함께 소개하는 콘텐츠로 운영한다.
- 이유: 원더핀의 핵심 제품은 장소 추천만이 아니라 장소·프로그램·운영자·예약을 연결하는 흐름이므로, 초기 인스타그램에서도 가족이 실제 참여할 프로그램 수요를 확인해야 한다.
- 영향: 소개 대상은 박물관·기관이 직접 운영하는 공식 프로그램, 공공·기관 연계 프로그램, 사설 운영자 프로그램을 모두 포함할 수 있다. 단, 원더핀이 직접 검수하거나 판매하지 않는 프로그램은 원더핀 프로그램처럼 보이게 표현하지 않고 운영 주체, 예약, 비용, 일정과 출처를 명확히 구분한다.
